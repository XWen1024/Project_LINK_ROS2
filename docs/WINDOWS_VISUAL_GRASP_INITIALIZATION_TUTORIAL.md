# Windows YOLO World + SO-101 从初始化到抓取教程

本文用于在一台 Windows 电脑上直接连接 USB 摄像头、SO-101 和
ESP32-C3 + VL53L0X，完成 LeRobot 校准、YOLO World 跟踪、参数调整和第一次监督抓取。
这个模式不依赖 ROS 2，也不需要 Orin。

Windows 测试台会独占摄像头和两个串口。运行时必须关闭旧版 VisualTracker、
VL53L0X Monitor、串口调试工具以及 Orin 侧视觉抓取节点，避免多个程序同时占用硬件。

## 1. 安全准备

- 机械臂周围至少留出一个完整臂展，移走玻璃、人体和易碎物。
- 校准会关闭扭矩，机械臂可能突然下坠，必须全程用手托住。
- 准备机械臂物理断电或急停；GUI 的“紧急停止并关闭扭矩”不能替代物理断电。
- 第一次测试不要让底盘移动，不要同时运行 Nav2 或其他自动任务。
- 先用轻软物体测试，夹爪闭合位置必须从保守值开始。

空的 `lerobot` 顶层包。

## 3. 连接硬件并识别端口

1. USB 摄像头连接 Windows，记住设备索引，通常从 `0` 开始。
2. SO-101 控制板连接 Windows，在设备管理器确认对应 COM 口。
3. ESP32-C3 使用原生 USB Serial/JTAG 口连接 Windows。该设备通常显示
   `303a:1001`，不要误选其他 CH340 串口。
4. 机械臂上电，但暂时不要启用扭矩。
5. 让相机能完整看到目标和夹爪前方区域。

端口不确定时，先拔掉设备，点击“刷新串口”，再插入设备并再次刷新；新增的 COM 口
通常就是目标设备。

## 5. 第一次 LeRobot SO-101 校准

没有有效校准文件时，普通“连接机械臂”会明确提示校准缺失。不要调用 LeRobot 原生
交互式 `robot.calibrate()`；Windows GUI 已提供不依赖终端 Enter 的完整校准流程。

### 5.1 开始校准并卸力

1. 在“硬件连接”选择 SO-101 COM 口。
2. 打开“关节、姿态与示教”页。
3. 用一只手托住机械臂。
4. 点击“1. 开始校准并卸力”，阅读安全确认后继续。
5. 等待状态变成“等待记录中位”。此时扭矩必须保持关闭。

### 5.2 摆到中位并记录 homing

1. 分别把底座旋转、肩、肘、腕、腕部旋转摆到各自可用行程的中间位置。
2. 把夹爪摆到开合行程的中间位置。
3. 中位不是机械臂抓取姿态，而是每个电机安全行程的几何中间附近。
4. 点击“2. 记录中位并开始采样”。

### 5.3 记录全部安全行程

状态变成“正在采样全行程”后，软件每 `50 ms` 自动读取原始编码器位置：

1. 缓慢移动底座旋转到两个安全端点，再回到中间。
2. 依次移动肩、肘、腕和腕部旋转，每个关节至少完整往返一次。
3. 夹爪必须从安全全开移动到安全闭合，再回到中间。
4. 不要用力撞击机械限位；记录的是安全可用行程，不是破坏性极限。
5. 确认六个电机都明显移动过。

### 5.4 完成并保存

1. 点击“3. 完成并保存校准”。
2. 再次确认全部关节和夹爪已经走遍安全行程。
3. GUI 显示“校准可用”以及 LeRobot 校准文件路径后，校准完成。
4. 机械臂仍保持连接，但扭矩关闭。
5. 关闭并重启测试台，再次点击“连接机械臂”，验证校准文件能冷启动加载。

冷启动时如果校准文件存在，但电机 EEPROM 中的 homing 或行程值与文件不一致，新版会
在扭矩关闭状态下自动把已保存文件重新写回六个电机，并立即读回验证。自动恢复成功时
状态直接进入“校准可用”，不需要重新摆中位或重新走全行程。只有文件不存在、写回失败
或读回仍不一致时，GUI 才会要求重新校准，并在消息中列出具体关节和字段差异。

STS3215 在关节越过 homing 零点时，会把负位置编码成带最高位的 16 位值，例如
`32952` 实际表示 `-184`，`32774` 实际表示 `-6`。旧 Windows 采样器把这些值误当成
很大的正数，而电机的 12 位限位寄存器只能保存 `0..4095`，因此读回会变成 `4095` 并
造成每次启动都判定校准失配。新版会先解码负位置，再根据完整安全行程自动调整 homing，
把每个关节范围重新居中到 `0..4095` 后才写入和保存。

已经包含 `range_min/range_max > 4095` 的旧文件无法自动恢复丢失的另一侧极值，需要使用
新版重新校准一次。完成后的文件中所有六个关节都必须满足
`0 <= range_min < range_max <= 4095`；之后冷启动可以自动加载，不应再次要求校准。

如果提示某个关节没有移动，点击“取消校准”，重新执行并确保遗漏关节完整往返。
任何步骤不确定时直接取消；取消会断开机械臂并保持扭矩关闭。

## 6. 验证关节方向和夹爪

1. 普通连接机械臂，确认状态为“校准可用”。
2. 点击“读取当前位置到目标栏”，检查六个读数是否稳定且合理。
3. 托住机械臂并勾选“启用机械臂扭矩”。
4. 每次只把一个关节目标改变 `1` 到 `2`，点击“发送五个机械臂关节”。
5. 确认关节方向与预期一致，再测试下一个关节。
6. 用保守位置分别测试夹爪打开和闭合，禁止夹持手指或硬物。

方向错误、跳变、异响或持续顶住限位时，立即点击顶部紧急停止并物理断电。

## 7. 录制三个预设姿态

建议按以下顺序录制：

1. `standby`：机械臂收拢、不挡相机、运输安全。
2. `pregrasp`：夹爪位于相机视野和桌面抓取区附近，尚未接触物体。
3. `placement`：用于把物体放入托盘或固定容器。

每个姿态先手动小步调整并确认安全，再点击对应“录制”。随后逐个点击“前往”验证。
预设姿态保存在：

```text
%APPDATA%\ProjectLINK\visual_grasp_lab\positions.json
```

重新完成 LeRobot 校准后，旧预设姿态会被自动清除。校准范围变化后，相同的归一化关节值
可能对应不同物理角度，继续使用旧预设可能把关节推向极限，因此必须重新录制三个位姿。

三个姿态的固定职责如下：

- `standby` 待机位：任务开始前和任务结束后的安全收拢姿态。系统不会因为开始跟踪就
  自动前往待机位；由操作员或上层任务流程明确调用。
- `pregrasp` 待抓取位：夹爪位于相机和目标抓取工作区附近，是视觉居中和逼近的起点。
  “开始自动抓取”必须先自动前往该姿态，抵达后才允许视觉伺服移动。
- `placement` 放置位：已经夹取物体后前往托盘或容器的位置。基础自动抓取只负责夹取，
  不会自动放置；确认抓取成功后由操作员或任务中枢调用放置位，再打开夹爪。

按钮权限按动作类型分开：

- 扭矩关闭且已确认卸力：允许读取关节、录制三个姿态和手动摆放机械臂。
- 扭矩开启：允许前往三个姿态、发送关节、控制夹爪和开始自动抓取。
- “开始目标跟踪”：只启动 YOLO 检测，不改变机械臂姿态，也不要求扭矩开启。
- “停止当前运动”：只停止机械臂运动；如果目标跟踪仍开启，可以继续显示检测框。
- “停止跟踪”或紧急停止：控制器回到 `IDLE`，不会因为停止动作而进入 `TRACKING`。

推荐人工流程：

```text
连接机械臂并保持扭矩关闭
→ 手动摆放并录制 standby / pregrasp / placement
→ 启用扭矩
→ 前往待机位，确认方向
→ 开始目标跟踪，只观察检测框
→ 点击开始自动抓取
→ 系统打开夹爪并自动前往 pregrasp
→ 抵达后执行居中、逼近和夹取
→ 抓取成功后前往 placement
→ 打开夹爪
→ 返回 standby
```

## 8. 验证摄像头和 YOLO World

1. 在“运行与自动抓取”页选择摄像头索引并连接。
2. 若无画面，依次尝试 `0`、`1`、`2`，同时关闭浏览器和会议软件的摄像头占用。
3. 在“参数与日志”确认模型路径指向 `yolov8s-worldv2.pt`。
4. 输入英文目标，例如 `medicine bottle`、`red cup` 或 `remote control`。
5. 点击“开始跟踪”，此时先不要启用扭矩，也不要开始自动抓取。
6. 移动物体，确认框稳定跟随且日志没有模型错误。

先调 `yolo_conf_threshold` 和目标文本，再调视觉伺服参数。不要为了偶尔检出而把置信度
降得过低。

## 9. 校正画面中心和视觉伺服方向

1. 保持扭矩关闭，把目标放在希望夹爪对准的位置。
2. 调整 `center_offset_x` 和 `center_offset_y`，让控制中心与真实抓取方向一致。
3. 启用扭矩，但暂时保持自动抓取停止。
4. 使用很小的 `pan_gain`、`tilt_gain` 和 `move_step_limit` 开始。
5. 点击开始跟踪，再开始自动抓取，观察机械臂是否朝减少画面误差的方向移动。
6. 只验证居中后立即停止，不要在未验证方向时让机械臂持续逼近。

如果任一轴朝错误方向移动，立即停止并检查增益符号、相机安装方向和电机校准。

预设位移动和视觉逼近是两种不同动作：

- “前往待机位/待抓取位/放置位”使用五关节同步 S 曲线，从当前姿态按时间插值到完整
  目标姿态，不再按反馈每帧追一点，也不再先伸展后旋转底座。
- “开始自动抓取”抵达待抓取位后才进入视觉伺服。居中每帧修正受
  `move_step_limit` 限制；逼近受 `joint_command_limit` 和 `grasp_timeout_sec` 保护。
- 到达软限位仍没有满足夹取条件时，控制器进入 `ERROR` 并停止，不允许继续伸到机械极限。

建议先把摄像头和自动抓取关闭，只启用扭矩并依次测试三个“前往”。确认轨迹平滑且每个
姿态正确后，再单独测试目标跟踪，最后测试自动抓取。不要一次同时调预设轨迹、中心增益
和 ToF 阈值。

## 10. 连接和标定 VL53L0X

1. 选择 ESP32-C3 对应 COM 口并点击“连接 ToF”。
2. 状态应显示约 `15` 到 `20 Hz`，有效样本持续增加。
3. 先只勾选“启用 ToF 数据”，保持“允许 ToF 控制逼近和闭合”和
   “抓取距离已现场标定”关闭。
4. 用卷尺比较 GUI 距离和夹爪接触点到目标的真实距离。
5. 记录至少 10 次接近过程，确认距离单调、遮挡和拔线能被识别。
6. 把安全抓取距离写入 `tof_grasp_distance_m` 并保存参数。
7. 只有现场测量完成后，才勾选“抓取距离已现场标定”。
8. 最后才允许勾选“允许 ToF 控制逼近和闭合”。

ToF 控制启用后，数据过期、样本不足或传感器故障必须进入 `RANGE_WAIT` 并停止逼近，
不能退回目标框面积自动闭合。

## 11. 第一次监督抓取

1. 使用轻软、尺寸明显的单个物体，背景尽量简单。
2. 前往 `pregrasp`，确认夹爪打开、机械臂空间安全。
3. 输入准确的 YOLO World 英文目标并开始跟踪。
4. 确认检测框连续稳定，ToF 距离有效。
5. 人员站在物理断电位置旁，启用扭矩。
6. 点击“开始自动抓取”。
7. 观察状态按“居中、逼近、距离等待或闭合”推进。
8. 成功夹取后点击停止，手动前往 `placement` 并打开夹爪。
9. 连续完成 3 次低速抓取后，才逐步提高增益或速度。

## 12. 以后每天的最快启动顺序

1. 清空机械臂空间并准备物理断电。
2. 启动 Windows 测试台。
3. 连接摄像头并确认画面。
4. 连接 ToF 并确认频率和距离。
5. 连接 SO-101，确认“校准可用”。
6. 读取关节并前往待机位。
7. 启用扭矩，前往待抓取位。
8. 输入目标并只跟踪观察数秒。
9. 确认 ToF 标定和控制开关符合本次测试目的。
10. 开始监督抓取。

## 13. 常见故障

- **连接后提示校准缺失**：执行第 5 节完整校准，不要反复点击普通连接。
- **明明保存过仍提示重新校准**：确认使用的 `robot_id` 是 `so101_slave`，文件应位于
  `%USERPROFILE%\.cache\huggingface\lerobot\calibration\robots\so101_follower\so101_slave.json`。
  新版连接会自动重新应用该文件；若仍失败，查看日志中的 `file=... motor=...` 差异，
  不要在原因不明时连续覆盖校准。
- **提示 `range_max file=329xx motor=4095`**：这是旧采样器的 Feetech 负位置回绕错误，
  不是文件没有保存。退出旧 GUI，启动最新版并重新做一次完整校准；新版会解码和重新
  居中，保存前也会拒绝任何超出 `0..4095` 的范围。
- **`id=4` 或 `id=5` 报 `Overheat error`**：4 号是 `wrist_flex`，5 号是
  `wrist_roll`。立即物理关闭机械臂电源，托住机械臂并等待电机完全冷却；不要重新启用
  扭矩，也不要开始校准。检查腕部是否顶住限位、负载过大或长时间持续发力。
- **过热后校准提示 COM 口无法连接**：旧流程可能在断扭矩异常时没有执行串口
  `closePort()`。物理断电后退出整个 Windows 测试台，等待 2 秒再重新启动。新版会先逐
  电机重试，再同步广播 `Torque_Enable=0`，最后无条件关闭串口，避免再次遗留 COM 占用。
- **所有 1 到 6 号电机同时提示 `[TxRxResult] Port is in use!`**：通常不是 COM24 被其他
  Windows 程序占用，而是同一 GUI 内的状态轮询与校准线程同时访问 Feetech 总线。新版会
  串行化所有机械臂 I/O、连接和校准期间暂停关节轮询，并清除 SDK 遗留的 `is_using`
  标志后重试。完全退出旧 GUI 后重新启动新版再测试。
- **提示“扭矩已关闭但电机存在硬件告警”**：同步广播和读取已经确认扭矩为关闭，
  但过热状态仍然存在；这不代表可以继续运行，仍须物理断电和冷却。
- **提示“关闭未确认”**：软件无法确认所有电机已经卸力，必须立即物理断电。
- **校准时电机仍发力**：立即物理断电，检查是否选错 COM 口或仍有旧程序占用硬件。
- **完成校准提示关节未移动**：取消后重来，让该关节和夹爪完整往返。
- **刷新串口和扭矩控件重叠**：确认运行的是仓库最新 Windows 测试台，而不是旧缓存脚本。
- **摄像头黑屏**：关闭其他摄像头程序，更换索引或重新插拔摄像头。
- **YOLO 无检测**：检查模型路径、英文类别、画面光照和置信度。
- **ToF 无数据**：确认选中 ESP32-C3 原生 USB 口，关闭其他串口程序。
- **自动抓取不启动**：检查机械臂连接、校准、扭矩、目标检测和 ToF 标定门。
- **机械臂方向错误**：立刻停止，复查中位、行程校准、相机方向和增益符号。
- **前往预设位时边抖边伸展**：旧版本使用反馈增量移动并最后才旋转底座。重启最新版，
  重新录制姿态后再测试；新版应显示 `Moving smoothly` 和进度百分比。
- **机械臂已到待抓取位但左上角显示 `ERROR`**：先打开“参数与日志”页查看
  `控制器错误`。新版会优先确认实际到位，不会只因刚好跨过 `move_timeout_sec` 就报错；
  完整五关节命令也不会再因写入前的一次冗余反馈读取失败而报假故障。
  真正超时会显示类似 `shoulder_lift.pos error=+3.20` 的剩余误差。若错误提示
  `Pregrasp pose is outside visual-servo soft limit`，说明录制的待抓取位本身超过
  `joint_command_limit`，应先关闭扭矩并重新录制更居中的待抓取位，不要直接放大软限位。
- **超时误差集中在一个接近 `+/-100` 的关节**：这表示预设录在校准行程端点附近，通常
  不是反馈卡住。例如目标 `elbow_flex=-98.84`、误差 `-8.53` 表示实际约停在 `-90.31`。
  点击停止，关闭扭矩，把该关节向中间收回至少几个归一化单位，再重新录制姿态。新版用
  `preset_joint_limit=95` 在录制和执行时提前阻止这种不可达预设。
- **待机位需要保存为接近初始收拢位置**：待机位不参与视觉逼近，默认允许使用独立的
  `standby_joint_limit=99.5`，因此可以比待抓取位和放置位更接近校准端点。保存时出现
  `extended supervised endpoint allowance` 属于提示而不是失败。执行时保持空载和人工监督；
  如果电机持续嗡鸣或机械结构顶住，仍应立即停止并把该关节稍微向中间收回。
- **非端点姿态只有肘关节残差约 `3..5`**：保留普通关节 `arrive_threshold=2.0`，将
  `elbow_arrive_threshold` 设为 `5.0`。肘关节承受机械臂重力，反馈通常比其他关节存在
  更大的静态偏差；不要因此把全部关节的到位容差统一调大。
- **远距离预设偶发 `error=2.03 tolerance=2.00`**：这是归一化反馈的量化、齿隙和负载
  造成的硬阈值边缘抖动。LeRobot 官方 `send_action()` 只写入 `Goal_Position` 后立即返回，
  不提供“运动完成”回调；`Present_Position` 又是按校准 min/max 线性映射到 `-100..100`
  的反馈。新版因此采用两级判定：先按严格容差连续确认；若只超出很小余量，则要求反馈
  在 `arrive_stable_delta=0.35` 内稳定 `arrive_stable_cycles=5` 次，并且误差不超过严格
  容差加 `arrive_stable_margin=0.75`，再判定完成。大误差和端点姿态仍然不会被放行。
- **自动抓取刚到待抓取位就提示 `Visual servo joint safety limit`**：说明预设本身尚在
  软限位内，但第一帧画面居中修正要求继续向限位方向移动。新版会将该帧命令钳位在
  `joint_command_limit` 并继续观察，不会立即报错；若连续
  `centering_limit_hold_cycles=3` 个新 YOLO 结果仍顶住限位，则应把待抓取位向中间调整，或重新标定
  `center_offset_y`，而不是提高关节软限位。
  Windows 画面中的黄色十字是期望中心，绿色圆点是目标框中心。若更换过相机、校准或
  机械臂姿态，先把 `center_offset_x` 和 `center_offset_y` 都设为 `0`；确认目标大致位于
  画面中心后，再每次以 `5..10` 像素小步调整。旧值 `143/61` 不一定适合当前安装。

更快的方法是点击视频下方“点击画面设置视觉抓取中心”，按钮进入选择状态后，在希望
目标框中心最终停留的位置点击一次。程序会自动处理视频缩放和上下/左右黑边，立即填写、
应用并保存 `center_offset_x/y`。黄色十字会移动到新位置；如果点错，点击“恢复画面中心”
后重新选择。手动点击会同时关闭并清除自动纵向锁定，后续自动抓取不会覆盖这个点。该功能
设置的是二维视觉伺服中心，不会在点击时移动机械臂。

这里必须点击“绿色检测框中心最终应该停留的位置”，不是点击瓶底、瓶盖或夹爪准备接触
物体的位置。若不确定，先点击“恢复画面中心”；也可以在绿色框稳定后点击“使用当前绿色
圆点”。当前 `centering_tilt_motion_enabled=0` 时，X 坐标参与真实水平居中，Y 坐标仅作为
黄色参考点和试教轨迹参考。需要改变机械臂实际抓取高度时，应重新录制 pregrasp。

若整体路径正确、只是最终夹爪比物体低一点，可在“参数与日志”页使用
`approach_profile_wrist_trim`。先保持夹爪部分闭合值 `40..45`，从 `0` 改为 `+2` 做一次监督
测试；如果夹爪变得更低，立即恢复 `0` 并改试 `-2`。确认方向后每次只增加 2，绝对不要
超过软件限制的 `-10..+10`。该参数只修改腕关节终点，不会提高肩关节行程上限。

- **检测框偶发跳动并带着机械臂来回摆**：新版不会再始终选择瞬时最高置信度框，而是优先
  关联上一稳定框，拒绝中心跳变超过 `yolo_max_center_jump_ratio=0.12` 或面积变化超过
  `yolo_max_area_change_ratio=1.8` 的候选，并最多保持旧框 4 帧。控制器只对每个新 YOLO
  结果动作一次，不会对同一旧框重复发命令；居中使用 3 个新结果的中值误差、远距离最大
  步长 `1.5`、近中心自动减速和连续 2 次确认。`yolo_infer_interval_sec` 建议保持 `0`，
  不要靠降低 YOLO 频率防抖，也不要通过提高增益追逐抖动框。
  异常跳变期间框会显示为橙色并带 `HELD`，此时机械臂不会发送居中或逼近命令。
- **框在纵向越调越远并最终撞向 `shoulder_lift` 软限位**：检查 `tilt_direction`。当前
  相机和 SO-101 安装应使用 `-1`。2026-08-10 的现场日志中，目标框中心从约 `y=340`
  被错误修正到 `y=308`，而目标中心为 `y=568`，证明旧方向 `+1` 与当前安装相反。
- **状态一直是 `CENTERING`，机械臂看起来不动，最后 `Visual grasp timed out`**：先看详细
  日志中的 `requested`、`Goal_Position` 和 `Present_Position`。如果每次请求只比反馈多
  `1.5`，但反馈和画面误差长期完全不变，说明小目标没有克服肩关节负载或静摩擦。新版会
  累计视觉伺服目标，但通过 `centering_max_command_lead=4.0` 限制目标最多领先实际反馈
  4 个归一化单位。现场先保持 `4.0`；仍不动作可在随时能断电的条件下试 `5..6`，不要
  同时提高 `joint_command_limit`，也不要无限增大领先量。
- **已经显示 `APPROACHING` 但肩关节仍不往前走**：逼近也使用有界累计，参数为
  `approach_max_command_lead=4.0`。先确认 ToF 状态有效；若 ToF 正常但电机仍被负载卡住，
  可按同样方法小步试 `5..6`。任何异响、持续大电流或机械干涉都应立即停止并断开扭矩。
- **进入 `APPROACHING` 后末端突然向地面下砸**：旧版固定 elbow 多项式不适配当前校准，
  日志中 shoulder lift 约 `-80` 时会错误生成 elbow flex 约 `+83`。该公式已经完全删除，
  新版按最近一次示教的相对量联动肩、肘、腕，并在每次发送前检查关节跳变。如果仍看到
  大幅下压，说明仍在运行旧进程；立即物理断电，完全退出并重新打开上位机。
- **自动抓取持续伸到最大角度**：目标未满足面积或 ToF 夹取条件。检查检测框、
  `tof_grasp_distance_m` 和 ToF 控制状态；新版会在 `joint_command_limit` 或
  `grasp_timeout_sec` 到达时停止并报错，禁止继续顶限位。

## 14. 配置与回退

### 14.1 录制用于重写算法的 YOLO 视觉卸力示教

1. 固定目标物体和摄像头位置，连接摄像头、SO-101 和可选 ToF。
2. 输入准确的 YOLO World 目标文本并点击开始跟踪，等待绿色框连续稳定显示。
3. 如果需要，从扭矩开启状态先前往待抓取位；确认周围无碰撞后托住机械臂。
4. 在“关节、姿态与示教”点击“开始 YOLO 视觉卸力示教”。程序会停止控制、关闭扭矩，
   但保持 YOLO 跟踪；如果还没有可信绿色框，程序会拒绝开始。
5. 保持目标物体固定，先在起始位置停留约 1 秒，然后缓慢示教你希望的完整动作：先让
   目标框中心稳定，再沿你认为正确的水平轨迹逼近，同时尽量让绿色框中心保持在同一位置。
6. 如果画面显示 `HELD` 或目标暂时消失，停止向前，缓慢退回到重新出现稳定绿色框的位置；
   不要在目标不可见时继续示教前进。
7. 手动完成接近、夹爪闭合视角，并在最终位置停留约 1 秒，然后点击“停止并保存视觉示教”。
8. 在日志中确认样本数、可信视觉样本数以及 bbox 面积比例范围不是零。

CSV 保存到：

```text
%APPDATA%\ProjectLINK\visual_grasp_lab\demos\visual_demo_YYYYMMDD_HHMMSS.csv
```

CSV 包含六关节、bbox 坐标、中心、像素面积、画面面积比例、目标中心误差、YOLO 可信状态、
检测序号、ToF 距离和时间。当前 `visual_demo_20260810_190054.csv` 已用于首条试教轨迹：
从预抓取到闭合前，shoulder lift 约 `+34`、elbow flex 约 `+12.3`、wrist flex 约 `-54`。
后续再提供 2–3 条纯抓取示教，用于平均这些比例；禁止恢复旧固定多项式。

### 14.2 第一版视觉交接逼近测试

第一版不是强行让 YOLO 一直识别到夹爪闭合，而是在目标即将占满画面时主动交给 ToF：

```text
CENTERING -> APPROACHING -> FINAL_APPROACH -> GRASPED
```

首次测试按以下顺序进行：

1. 在待抓取位让绿色框稳定。默认 `auto_lock_vertical_center_on_pregrasp=0`，自动抓取使用
   你在视频页点击并保存的黄色对齐点。只有主动改成 `1` 时，第一帧可信绿色框才会覆盖本次
   纵向参考，并按 `auto_lock_vertical_center_offset_ratio=0.10` 下移框高 `10%`。
2. 参数保持 `centering_tilt_motion_enabled=0`；程序不会通过 shoulder lift 提前伸臂。需要
   微调时直接重新点击视频点位；需要改变真实高度时重新录制待抓取位。
3. 开启并确认 `tof_enabled=1`、`tof_control_enabled=1`、`tof_calibrated=1`。
   任一选项未开启时，视觉交接模式会在自动抓取启动前直接拒绝并列出缺少的开关。
4. 第一轮可暂时将 `gripper_close` 设为约 `40..45`，先验证交接和部分闭合，避免夹伤物体。
5. 开始自动抓取，确认状态先完成 `CENTERING`，再进入 `APPROACHING`。
6. 当框高度/面积或 ToF 进入近场门后，状态应显示 `FINAL_APPROACH`。此后框变为 `HELD`
   或完全消失不会中断最终抓取；这正是用于处理夹爪遮挡和物体顶满画面的阶段。
7. `FINAL_APPROACH` 中 ToF 无效时机械臂必须停止。ToF 小于
   `final_grasp_tof_m=0.090` 才闭合；超过 6 秒、shoulder lift 盲走超过 20 或到达“保存的
   pregrasp shoulder lift +34”终点并等待 `0.75 s` 后仍未达到阈值时进入错误。

首版参数来自现有示教，只用于有人监督的低风险验证。第一次复测先把目标放远、夹爪闭合值
设为 `40..45`，手放在物理电源处。进入 `APPROACHING` 后，日志首条 `approach_tick` 的正常
变化应接近：shoulder lift `+1.5`、elbow flex `+0.54`、wrist flex `-2.38`；任何单关节一次
变化接近几十度都不正常，必须立即断电。

“参数与日志”页左侧参数区可以独立上下滚动，鼠标滚轮不会再改变数值框。若只是误点或
误输入但还没保存，点击“撤销修改（恢复已保存）”；若已把滤波和运动参数调乱，点击
“一键恢复推荐参数”。推荐复位会立即保存，但不会改变摄像头、串口、模型路径和
`center_offset_x/y`。画面对齐位置应在视频页使用“恢复画面中心”或点击选点单独调整。

Windows 运行时文件位于：

```text
%APPDATA%\ProjectLINK\visual_grasp_lab\
```

其中：

- `config.json`：模型、摄像头、视觉伺服和 ToF 参数。
- `positions.json`：三个预设姿态。
- `demos\`：带 YOLO bbox、面积、误差、ToF 和六关节数据的视觉卸力示教 CSV。
- `logs\visual_grasp_debug_*.jsonl`：详细调试日志。

详细日志默认开启，也可在“参数与日志”页关闭。每次出现难以描述的问题时：

1. 保持详细日志开启并重启上位机；
2. 只复现一次故障，记录 GUI 中的准确时间；
3. 点击“写入当前机械臂快照”；
4. 正常退出上位机；
5. 点击“打开详细日志目录”，发送时间最新的 `.jsonl` 文件。

该文件包含启动参数、预设位置、校准数据、每个运动周期的目标和反馈，以及报错时的原始
Feetech 位置、目标、速度、负载、电流、温度、Moving、Status 和扭矩状态，不包含图像。

只有 GUI 的一键推荐复位也无法恢复时，才退出程序并备份该目录，再删除 `config.json`。
LeRobot 电机校准文件由 LeRobot 自己保存，不在此目录；不要把其他机械臂的校准文件
复制到当前 SO-101。
